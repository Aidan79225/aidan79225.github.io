# Day 25|上傳容易,刪除難:資源的生命週期

今天插一個看起來最不起眼的題目:**商品圖**。「不就是上傳檔案嗎」——這篇會用一半的篇幅講上傳,另一半講一件難得多的事:**刪除**。上傳只要一個下午就能做完;刪除,是一輩子的事。

## 生:一條為現場設計的上傳管線

商品圖哪裡來?直播現場操作平台的是助理(Day 14),而圖的來源是:**看直播截圖,貼進我們前端的 dialog,確認,上傳。**主播拿著貨在鏡頭前講,助理把畫面截下來,Ctrl+V——**商品圖的來源,就是直播本身**。

![整條管線為「直播現場、剪貼簿貼圖」量身訂做](day25-1.png)

前後端各做一次 webp 處理,乍看重工,其實是兩件完全不同的事:**前端切正方形、轉 webp,是優化**——截圖的長寬比什麼都有、現場頻寬珍貴;**後端不信前端,一律重編碼,是保證**——寫這篇時我回去查了當年的程式碼:webp 進來也重編碼一次,原始上傳的 bytes 一律不落地。

重編碼是檔案驗證這把梯子(副檔名→Content-Type→魔術數字→解碼→重編碼)最強的一層:解不開的檔,轉檔自己就失敗;能活過 decode+encode 的,必然是一張真的圖;藏在檔案裡的 payload、EXIF,全部在重編碼時銷毀。我們沒有寫任何一條「檢查檔案是否安全」的 if——**驗證不是流程前的關卡,是正常流程的副產品**:跟 Day 4 的「查詢即驗證」同一個哲學,這裡叫**轉檔即驗證**。

還有個小而美的細節:DB 裡存的是 **path(事實)**,API 回應時才解成完整的 **URL(派生)**——實際供圖走 GCS 掛 CDN。哪天換 CDN,改一行解析邏輯,零筆 migration。

## 死(一):每日 sweep,和一張從沒理賠過的保險單

圖存好了,誰記得它?`image_metadata` 表:存 GCS path,加上泛型外鍵指回擁有者(product/style)。**反向引用只為一件事——清理**:GCS 不在資料庫的管轄範圍裡,外鍵約束保護不了它,這張表等於把 FK 的紀律手動延伸到 blob storage 上。

那反向引用實際用了嗎?誠實時間:**沒有。**「反查是否還有人用」這條查詢從來沒被寫出來——它是一張**從沒理賠過的保險單**。實際的清理機制更簡單:助理**換圖**時,系統把舊的 metadata **標記待刪除**;**每日排程** sweep,真的刪掉 GCS 物件。

為什麼不反查也沒出事?因為**刪除的入口只有一個**:換圖。標記永遠是對的,反查自然多餘——但這是**僥倖版**的「結構讓它不必做」:哪天多了第二個刪除入口(批次匯入、商品複製),沒有反查的 sweep 就會開始誤殺。重來版一行結論:**sweep 前反查一次**,一條便宜的 query,把僥倖升級成保證。

## 死(二):我親手寫的 bug 產生器

資源的死講完了,講資料的死——**軟刪除**。這段是我的誠實失敗,源頭就是我寫的。

當年我定義了一個 `SoftDeleteModel`:`is_deleted` 欄位,配一個自訂 manager——**預設 queryset 只回傳未刪除的**,原本的 `objects` 改名叫 `all_objects`。然後,**全部 model 都繼承它**。用起來很舒服:每個查詢自動濾掉已刪的,乾淨。

![崩壞不是從 bug 開始的,是從「想加一個欄位卻改不動 base model」開始的——魔法的帳單,在混用的那天寄到](day25-2.png)

崩壞鏈:某天想加 `deleted_at`,但改 base model 會動到全部 model → 部分 model 取消繼承,**隱式和顯式開始混用** → 每個呼叫點都要先判斷「這個 model 是哪一派」→ 工程師乾脆一律用 `all_objects` → 忘記補濾 `is_deleted` 的 bug 開始出現。**bug 產生器**,是我對它的蓋棺定論。

病根在第一天:**`objects` 說謊**——它的名字承諾「所有物件」,行為卻是「未刪除的物件」。**半套抽象比沒有抽象更貴**:混用讓每個呼叫點多付一次判斷,而人在重複判斷面前一定會找捷徑,捷徑一定選錯邊。

重來版三條,全是「顯式」的變奏:**欄位存事實不存旗標**(`deleted_at` nullable timestamp——「刪了沒」用派生的,「何時刪的」第一天就有);**共用 QuerySet 不共用 base model**(`objects` 永遠誠實回傳全部,要濾就寫 `.active()`——繼承共用的是政策,組合共用的才是機制);**軟刪除是 per-table 的政策不是全域預設**——資料分三類,各有名正言順的死法:事實(order、payment)永不刪、被事實引用的主資料(product、style)軟刪、暫態(購物車)理直氣壯地硬刪。

**上傳是功能,刪除是責任**;**隱式是借來的方便**——利息在混用的那天開始計,最後用 bug 一次結清。

系統的故事到此告一段落。明天講做出這一切的人:六個工程師,怎麼跑出二十個人的速度。
