# Day 19|風控與黑名單:不是逐客令,是信用體系

先把攻擊模型講清楚。這個系統裡,留言喊單**當場佔庫存**、付款卻在檔期尾聲——中間隔著幾天的信任。惡意的玩法於是很簡單:**喊單、佔住、不付**。庫存被白佔最長一整週,真想買的客人搶不到——**惡意下單就是對庫存的 DoS**,而且發動成本是零:打幾個字而已。

## 分級懲罰:從一顆確認鈕到永 ban

不付款被抓到,不是一刀封殺,是**四級遞進**:

![四級階梯:第一級只要你「知道」,最後一級才是門](day19-1.png)

第一級是整座階梯的靈魂。它**不是懲罰,是簽收**:下次開網頁跳一個警示 dialog,按下確認、當場解鎖——什麼都沒失去,但「規則已告知」這件事完成了。這個設計的高明在:**讓第一級罰則便宜到誤殺無所謂**——真的忘了付、臨時出國的好客人,全部代價是按一顆按鈕,連客服都不用找。**偵測不用做到多準,因為判錯的傷害已經被結構吸收了。**

而慣犯不需要另外偵測——**他們自己會沿著階梯往上爬**:一個月、三個月、永 ban。這套「警告→輕罰→重罰→除名」的遞進,治理學裡叫 graduated sanctions,是管理公共資源的經典設計——當年沒有人讀過那些文獻,它是被業務直覺長出來的。

## 只禁喊單,不禁刷卡

被 ban 之後,實際上失去的是什麼?這是全篇我最喜歡的一刀:**banned user 只是不能在直播喊單——去商城刷卡付錢下單,照常歡迎。**

這個系統有兩種交易:**喊單是信用交易**(先佔庫存、檔期尾聲才付錢——中間那幾天,平台在給你信用);**商城刷卡是現金交易**(先付錢才有貨,不需要任何信任)。惡意不付款的人,濫用的是前者的信用——所以被拔掉的,精準地只有那個特權。**信用破產的人不是不能做生意,是只能現金交易**:銀行業幾百年的邏輯,在直播電商裡被重新發明了一次。**懲罰的顆粒度,對齊被濫用的信任的顆粒度**——罰其所犯,不多不少。

## 執行機關:一張表、一個 cache、一排按鈕

![快速判斷在 Redis、事實在 DB;三個入口、兩個出口,一鍵可查](day19-2.png)

- **banned user 表用泛型外鍵**:要封 fb user 封 fb user、要封 account 封 account,一張表通吃。**連坐是 account 級的**:封了帳號,名下綁定的身份一起生效;而且綁定的瞬間會更新 Redis——**新身份綁上被封的帳號,當場繼承前科**。
- **Redis 只做快速判斷,事實在 DB**:每則留言都要問「這人在不在名單裡」,高頻小查詢住 Redis;重啟從 DB 重建,結算檔期後用 pipeline 批次寫入。
- **留言瀑布一鍵拉黑**:主播和助理的 dashboard 上,黑名單標籤旁邊就是執法按鈕——情報卡和執法台是同一個畫面。
- **出獄有兩條路**:時效到自動解,客服介面手動解。

## 重來:給風控裝上眼睛

這篇的重來清單只有一項:**測量**。當年這套風控上線之後「沒收到負面 feedback」——但我們**沒有做任何相關測量**。擋掉多少惡意訂單?一級警告後多少人乖乖付款(改過率)?有沒有好客人被冤枉(誤殺率)?**全部不知道。**「沒收到抱怨」是沉默偏差,不是證據——被誤殺的客人最可能的反應不是申訴,是安靜地再也不來。**沒有測量的機制,連「它還在不在運作」都是信仰。**

三個帶得走的觀點:

1. **懲罰的設計,比偵測的設計重要。**當懲罰結構對了,偵測只要大致對(這套系統連模型都沒有,就看有沒有付款);當懲罰結構錯了(一刀永 ban),偵測再準都在製造冤案。
2. **治理的智慧,長在業務直覺裡。**分級制裁、規則簽收、罰其所犯——每個設計都能在治理文獻裡找到對應原則,而它們是現場磨出來的。好的系統設計者不是發明規則,是**聽懂現場已經在用的規則,然後把它變得可執行、可追溯**。
3. **風控的終點,是把人留下來。**階梯的每一級都留著回頭路——風控的目標不是驅逐,是修復信任。

營運面到此寫完。明天開始講仗打得最兇的地方:開賣瞬間——主播喊完 key 的那三秒。
