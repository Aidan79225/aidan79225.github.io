# Day 22|沒有 SRE 的年代:backend lead 的上線日記

昨天講尖峰怎麼打;今天講打仗的人。當年團隊沒有 SRE 這個職稱——身為 backend lead,infrastructure 的仗自然全落在我身上。這是那段提心吊膽日子的日記。

## 全部家當:一台 VM,一顆資料庫

先交代陣地。整個平台——traefik、四個 API process(Django,API 和 WebSocket 一起做)、三個 Celery 容器,連同 Redis 和 RabbitMQ——**全部擠在同一台 VM 上**(e2-custom-8-21504:8 vCPU、21 GB)。資料庫不自己養,直接用 Cloud SQL,開了 8 core。就這樣,兩台之力,扛住最高 13,000 人在線的直播。

![兩台之力:一台 VM 裝下全部元件,一顆管理式資料庫。厲害吧](day22-1.png)

用盡量少的資源做,是刻意的哲學,不是預算不夠。三個 Celery 容器的分工,是這個小陣地裡最有設計感的部分:**heartbeat** 跟 Django 結合做排程,所有「定時發生的事」心跳都從這裡來;**抓留言只有一個 worker**——不是省,是設計:單一 worker 天生序列化,Day 3 講的「單一抓取 job 自己定義了全域順序」,物理基礎就是這一個 worker;**async task 10 個 worker**,走 RabbitMQ,設 `acks_late`——做完才認,寧可重做,不可丟單。

## 監控:Sentry,和模模糊糊的我們

講難堪的部分:**監控基本上是純人肉**。當年的認知就到那裡——我們做到的只有用 Sentry 看 error。上線初期 Sentry 的容量一下就炸了,後來才學會加 sampling。團隊裡沒有人真的懂監控,我自己,大概也就是模模糊糊地看。

但 Sentry 有一筆真戰績——在 demo 階段。系統給其他部門試用,問題回報得七零八落;VM 裡的 log 有時被清掉,想查也查不到,這時 Sentry 就派上用場了。**log 是揮發的,error tracker 是留底的**——它的真實價值不是「監控」,是**持久化的錯誤記憶**。

盲區也要誠實說:error tracker 只看得到 exception。延遲變高、CPU 飽和、batch 越淤越深——這些都不會 raise,Sentry 一片綠,系統可能正在淹水。四個黃金訊號,我們只看得到 errors 一格。

## 跟播:四個視窗

剛上線的第一個月,每一場直播我都跟播。開四個視窗:

![四格監控,一格是量表、一格是 CPU、一格是抽查——最靈敏的那格,是直播的聲音](day22-2.png)

前三個視窗都還算正經:主播 dashboard 看數據有沒有進來、VM terminal 看各 container 的 CPU、Django admin 抽查 bidding key 狀態。真正的告警系統是第四個——**直播本身**。主播老闆一句「系統怪怪的」,比任何量表都快、都準:她站在使用者體驗的最前線。**她也是告警系統。**

跟播有一條退場曲線:第一個月每場跟;沒什麼問題後,變成 CTO 有問題才 call 我;後來,連 call 都沒了。人肉監控的退役,不是換上了更好的儀表板——是**不再需要看**。信任是用一場一場平安的直播慢慢買回來的。

## 半夜的電話,和事故的語言

半夜的電話不打給我,打給 CTO——而且他常常被這樣對待。電話裡不只有事故,還有**許願**:連許願的人自己都說不清楚要什麼的那種。

這件事我後來才想明白:當年缺的不只是監控,是**「事故的語言」**。沒有 severity 分級,「系統怪怪的」和「全站掛了」是同一通電話;沒有事故入口,回報問題的唯一介面是「打給職級最高的技術人」;沒有 runbook,每一通電話都是即興演出。許願的人說不清楚,不是因為不專業——是**系統沒有給他們描述問題的詞彙**。制度的本質是一部**翻譯機**:把人類的不安翻譯成系統的動作。沒有翻譯機,翻譯工作不會消失——它會沿著職級往上爬,在半夜響鈴。

## 重來:pipeline 蓋不到的那半張 checklist

上線那天有 checklist 嗎?沒有,硬著頭皮就上了——底氣是 CI/CD 和 staging 很早就位。事後看這半張底氣是真的:**可重複的部署,本身就是一張每天自動執行的 checklist**。但 pipeline 只保證部署是對的,**不保證部署之後扛得住**——容量、監控、告警,那半張紙上的每一項,後來都變成一場仗。重來補的就是那半張:負載測試(尖峰形狀已知,上線前重放一輪)、四個黃金訊號+batch lag、三級 severity+runbook、跟播轉為產品觀察。

**恐懼是最貴的監控。**那一個月,我用恐懼在付監控費。儀表板的意義不是讓你知道更多,是**允許你不看**——監控系統的終極產品,是安心。而**職稱可以缺席,問題不會缺席**:當年沒有 SRE 這個角色,但 SRE 的問題一個也沒少——沒人認領的問題,會自己長到離它最近的人身上。

明天換一個抽象的高度:這整個系統,其實是一台拆開的資料庫。
