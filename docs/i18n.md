# 多國語系(i18n)運作方式

這個站的母語是繁中,網址不帶語言前綴(`/blog/<slug>/`);英文版是**逐篇 opt-in 的翻譯**,
放在 `/en/` 底下,不是整站鏡像。沒翻譯的文章就只有中文,完全不受影響。

## 加一篇英文翻譯

1. 在 `src/content/blog/en/` 建立與原文**同名**的檔案,例如
   `src/content/blog/en/pain-before-power.md`。
2. frontmatter 照抄原文(`date` 保持一致),再加一行指回原文 slug:

   ```yaml
   translationOf: pain-before-power
   ```

3. 內文整篇翻譯;SVG 圖裡的 `<text>` 標籤與 `aria-label` 也要翻。
   `[[slug]]` wiki-link 照用 —— 它們固定解析到中文原文(`/blog/<slug>/`)。

完成後自動發生的事:

- 英文版取代 `/en/blog/<slug>/` 的中文 fallback 頁,並列在 `/en/` 索引頁。
- 中英兩篇互相顯示語言切換橫幅,`<head>` 輸出 hreflang alternates
  (`x-default` 指向中文)。
- OG 分享圖:跑 `npm run og`(pre-commit hook 也會自動跑)會產出英文標題版的
  `/og/en/<slug>.png`,分享 `/en/` 連結時預覽卡整張是英文。
- utterances 留言以 pathname 開 issue,中英文各自獨立一串。

## /en/ 的 fallback 機制

**`/en/` 底下每一條路徑都存在**,規則是:

1. 有真正英文版的頁面(`/en/`、`/en/about/`、已翻譯的文章)→ 顯示英文內容。
2. 其他全部 fallback 成中文內容:靜態頁靠 Astro 的
   `i18n.fallback` + `fallbackType: 'rewrite'` 自動產生(`/en/tech/`、
   `/en/tags/...` 等);文章頁由 `src/pages/en/blog/[slug].astro` 的
   getStaticPaths 明確涵蓋所有未翻譯文章。
3. 兩邊都沒有 → 404。

fallback 頁的防護(BaseLayout 統一處理,靠「locale prop 是 zh 但
`Astro.currentLocale` 是 en」偵測):

- `rel=canonical` 指回中文原網址,避免重複內容的 SEO 問題。
- 頁面頂端顯示「This page hasn't been translated yet」提示條。
- `<html lang>` 維持 `zh-Hant`(內容確實是中文)。

站內連結一律跟著**當前網址的 locale** 加前綴(`currentLocale()` +
`withLocale()`,見 `src/lib/i18n.ts`),所以從 `/en/` 出發怎麼點都不會
掉出英文區;Search 結果也在 client 端做同樣的處理。

## 架構備忘

- `getPublishedPosts()` **預設只回中文**(過濾掉 `en/` 前綴的 id),要英文文章
  明確傳 `getPublishedPosts('en')`。
- 語言由檔案路徑決定(`en/` 底下就是英文),不看 frontmatter;
  配對靠英文檔的 `translationOf`。
- UI 字串字典與 locale 工具在 `src/lib/i18n.ts`。
- Service worker **不 precache `/en/`**(幾乎都是中文內容的複本,precache 會讓
  首訪多下載約 10MB;英文區改為 online-only),規則在 `src/lib/sw-manifest.mjs`。
- 已知留白:RSS 與 search-index 只含中文;sitemap 會列出 fallback 頁(canonical
  已處理);graph 視覺化內的節點連結未加前綴(點了會回到中文區)。
