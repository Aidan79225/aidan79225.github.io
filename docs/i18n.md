# 多國語系(i18n)運作方式

這個站的母語是繁中,網址不帶語言前綴(`/blog/<slug>/`);英文版是**逐篇 opt-in 的翻譯**,
放在 `/en/` 底下,不是整站鏡像。沒翻譯的文章就只有中文,完全不受影響。

## 加一篇英文翻譯

1. 在 `src/content/blog/en/` 建立與原文**同名**的檔案,例如
   `src/content/blog/en/pain-before-power.md`。
2. frontmatter 照抄原文(`date` 保持一致),再加一行指回原文 slug:

   ```yaml
   translationOf: pain-before-power
   ```

3. 內文整篇翻譯;SVG 圖裡的 `<text>` 標籤與 `aria-label` 也要翻。
   `[[slug]]` wiki-link 照用 —— 它們固定解析到中文原文(`/blog/<slug>/`)。

完成後自動發生的事:

- 英文版出現在 `/en/blog/<slug>/`,並列在 `/en/` 索引頁。
- 中英兩篇互相顯示語言切換橫幅,`<head>` 輸出 hreflang alternates
  (`x-default` 指向中文)。
- OG 分享圖沿用中文版的(`/og/<原文 slug>.png`),不需要重跑 `npm run og`。
- utterances 留言以 pathname 開 issue,中英文各自獨立一串。

## 架構備忘

- `getPublishedPosts()` **預設只回中文**(過濾掉 `en/` 前綴的 id),所以首頁、
  tags、RSS、search-index、graph、backlinks 全部維持純中文;要英文文章明確傳
  `getPublishedPosts('en')`。
- 語言由檔案路徑決定(`en/` 底下就是英文),不看 frontmatter;
  配對靠英文檔的 `translationOf`。
- UI 字串字典在 `src/lib/i18n.ts`(版型、PostCard、footer 用)。
- 尚未國際化(之後有需要再做):RSS 與 search-index 只含中文、tag 頁只列中文文章、
  Nav 沒有全站語言切換(靠文章內橫幅與 `/en/` 索引頁)。
