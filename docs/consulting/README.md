# 顧問工具包

`/consulting/` 頁面背後的實際工作流程與範本。從詢問表單進來的第一封信,到結案請推薦,每一步都有可以直接複製使用的東西。

> ⚠️ **這個 repo 是公開的。** 這裡只放**空白範本**。填了客戶名稱、系統細節、報價金額的版本
> **一律不要 commit**,放在私人的地方(Google Drive、Notion、本機加密資料夾)。
> 簽了 NDA 的案子更要注意。

## 流程總覽

```
詢問表單 ─→ 初談(30 分)─→ 提案報價 ─→ 簽約收訂金 ─→ Kickoff ─→ 執行 ─→ 交付 ─→ 結案
   │            01              02          03           04        04/06     05      08
   └─ 不適合就禮貌婉拒(01 有範本)
```

| # | 檔案 | 什麼時候用 |
|---|---|---|
| 01 | [初談](01-intro-call.md) | 收到表單後回信、30 分鐘初談的問題清單、判斷接不接 |
| 02 | [提案與報價](02-proposal.md) | 初談後 2–3 天內寄出的提案 |
| 03 | [合約重點](03-agreement-checklist.md) | 簽約前逐項確認 |
| 04 | [Kickoff 與盤點](04-kickoff-and-discovery.md) | 健檢 / 可靠度盤點的開場、資料請求、訪談題目、技術檢查清單 |
| 05 | [健檢報告](05-assessment-report.md) | 健檢與盤點的主要交付物 |
| 06 | [諮詢與陪跑](06-sessions.md) | 單次諮詢的會前問卷與會後整理、陪跑的每次紀錄 |
| 07 | [定價試算](07-pricing.md) | 決定報價、之後調價 |
| 08 | [結案](08-closeout.md) | 結案信、回饋問卷、請推薦與案例授權 |

## 使用原則

- **先診斷,再開藥。** 初談只聽不給解法,解法是付費的部分。
- **範圍寫死。** 提案裡的「不包含」跟「包含」一樣重要。追加需求另外報價,不要順手做。
- **報告寫給會讀的人。** 老闆讀摘要,工程師讀發現清單,兩種都要照顧到。
- **每個案子結束都要留下東西**:一則推薦、一個可公開的案例、或至少一個學到的教訓,回頭更新這份工具包。
- **正職優先。** 不接與現職公司業務重疊的案子,不用到公司任何資訊與資源,會議排在不影響正職的時段。
