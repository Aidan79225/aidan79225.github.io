# 成為 Tech Leader 讀書筆記 — 系列 Roadmap

內部規劃文件(不發佈;Astro 不會 build `docs/`)。系列鍵:`series: "成為 Tech Leader 讀書筆記"`。
書:*Becoming a Technical Leader: An Organic Problem-Solving Approach*(Gerald M. Weinberg,Dorset House 1986;中譯《領導者,該想什麼?》,經濟新潮社)。

定位:全站唯一的**軟技能/領導力**系列。技術系列講系統怎麼運作,這個系列講「帶系統的人」怎麼長出來——領導力=影響力而非職位,用 organic(園丁)而非 linear(棋手)的方式帶團隊。書分五部:定義 → 創新 → 激勵 → 組織 → 蛻變,MOI 模型(Motivation / Organization / Innovation)是全書骨架,前六篇已把「定義」走完、「創新」開了頭。

節奏:不是嚴格一章一篇——概念相近的章節可以併成一篇(btl-1 就併了 Ch1+Ch2),以「一篇講清楚一個模型」為準。寫好一篇 → `draft: true` 改 `false` 發佈。
**注**:第 7 篇以後的章節對應與分組是預先規劃,動筆時以手上的書為準,可再拆併。

## 術語表(Ubiquitous Language)

書:*Becoming a Technical Leader: An Organic Problem-Solving Approach*(Gerald M. Weinberg,Dorset House 1986)。**英文欄填原書用字**;標 ⚠ 的是我從中文回推、尚未對過原文的,動筆或翻譯時翻書確認後改掉。

全系列同一個概念只准一個中文寫法;英文欄是翻譯時直接照抄的來源。
寫到表上沒有的術語就補一列。跨系列共用的通用詞(快取、佇列、可觀測性)在
`docs/en-translation-glossary.md` B 區,這裡只放本系列特有的。

## 寫每篇時的慣例
- front matter:`series: "成為 Tech Leader 讀書筆記"`、`seriesOrder: <#>`、`category: tech`、`comments: true`、`draft: true`(寫好再發)。
- 標題慣例:「領導力 - X」(btl-1 例外,就叫「領導力」)。
- tags 用 ASCII:`leadership` + 該部主題(Part Two 加 `innovation`、Part Three 加 `motivation`、Part Four 加 `organization`)。
- 依 `.claude/skills/writing-blog-post`:摘要比原書更清楚(提煉成模型/對照)+「## 反思」放真實經驗——**這個系列的反思口吻就是全站的口吻範本**,反思是賣點,不能省。
- 有空間結構的概念配站台深色 SVG(SVG 內不可有空行);純反思篇可以合法略過圖(skill 明文允許)。
- 台灣用語(見 `docs/zh-tw-style-guide.md`)。
- 跨篇用 `[[btl-x]]` / `[[btl-x#段落]]` 互連(btl-5 ↔ btl-6 已示範);跨系列可連 `[[pain-before-power]]`(成長峽谷/先蹲後跳的實戰版)、`[[blog-as-a-product]]`(把自己的產出當系統經營)。
