# 台灣用詞與個人口吻風格指南設計

- 日期:2026-06-19
- 範圍:讓 AI 協作寫出的部落格文章**用台灣技術用語、且讀起來像作者本人**,並用一套會隨修正成長的機制持續逼近。
- 站台:Astro(master 上線中)

## 背景

AI 產出的文章常出現(1)中國/非台灣慣用的技術術語(代碼、函數、默認、緩存…),與(2)不像作者本人的語氣(中立複述、AI 腔的連接詞堆疊)。需要一套系統化做法避免,而不是每篇靠人工抓。

口吻基準已確認:以作者親手寫的 **`btl-1`~`btl-6` 的「## 反思」段**為範本。

## 已確認決策(A + B + C 合併)

- **C(源頭)**:建一份會成長的活文件 `docs/zh-tw-style-guide.md`(完整對照表 + 口吻準則 + 寫作慣例 + 修正記錄)。
- **A(內嵌)**:把**核心規則直接寫進** `writing-blog-post` skill(最常見的對照詞 + 口吻錨點 + 掃描指示),確保每次寫文一定看到,不只放指標。
- **B(把關)**:每篇 draft **收稿前**用對照表 grep 內文,抓出禁用詞改掉。
- skill 放精簡核心、doc 放完整版,互補不重複(skill 明確指向 doc 為完整來源)。

## 設計內容

**B 區 — 口吻準則**(以 btl 反思為範本):
- 第一人稱、有主張(「我認為」「我的習慣是」「我會先…」),不中立複述。
- 用具體經驗 / 數字 / 真實情境佐證,不泛論。
- 轉折愛用破折號「——」;常用「其實」「往往」「與其…不如」。
- 段落 / 文章結尾常收一句斬釘截鐵的判斷或原則。
- 句長交錯,長短句搭配,不要每句都長。
- **範本指標**:寫新文的「## 反思」前,先讀一兩篇 `btl-*` 的反思抓語感。

**C 區 — 中文寫作慣例**:
- 引號用「」『』,不用 `" "`;破折號用「——」。
- **避免 AI 腔**的連接詞堆疊:首先 / 其次 / 再者 / 最後、綜上所述、總而言之、值得一提的是、值得注意的是、不僅…而且、眾所周知、總的來說。
- 中英之間、數字與中文之間視情況留空格(沿用現有文章習慣)。

**D 區 — 修正記錄(append-only)**:四欄 `日期 | 原(AI 寫的) | 改(偏好) | 類型(詞/口吻)`。每次作者糾正就追加一列,並視情況把新詞補進 A 區表。這是「越用越像你」的成長機制。

### 2. `writing-blog-post` skill 修改(A + B)
在 SKILL.md 新增一節 **「## 台灣用詞 & 口吻」**,內容精簡:
- 內嵌**最高頻**的對照詞(約 15 條:代碼→程式碼、函數→函式、變量→變數、對象→物件、默認→預設、緩存→快取、數據→資料、返回→回傳、運行→執行、實現→實作、調用→呼叫、用戶→使用者、項目→專案、配置→設定、文件(file)→檔案)。
- 口吻錨點:反思段以 `btl-*` 反思為範本 + B 區那幾條特徵。
- **收稿前掃描(B)**:完成 draft、回報前,用 A 區對照表 grep 一遍內文,抓到禁用詞就改。
- 一句指標:**完整對照表、口吻準則、修正記錄見 `docs/zh-tw-style-guide.md`**。

### 3. 修正流程
作者指出某詞/句法不對 → 追加到 D 區修正記錄(必要時補進 A 區表 + skill 高頻清單)。

## 不在範圍(階段二)
- CI 自動把關(PR 時 grep 到禁用詞就 fail build)。先用人工收稿掃描,日後想更硬再加。

## 風險 / 注意
- **誤殺**:有些詞兩岸通用或依語境(支持 / 通過 / 優化),對照表用「備註」標清楚,掃描時人工判斷,不要無腦取代。
- skill 與 doc 重複導致漂移:skill 只放「高頻核心 + 指向 doc」,完整表只在 doc 一處維護。

## 驗證方式
- `docs/zh-tw-style-guide.md` 存在且含 A/B/C/D 四區與種子對照表。
- `writing-blog-post` SKILL.md 有「台灣用詞 & 口吻」節:含高頻對照詞、口吻錨點、收稿掃描指示、指向 doc。
- **順手稽核現有草稿**:用 A 區禁用詞 grep `src/content/blog/*.md`(Airflow/Spark/dbt 等),列出命中處;若有則修掉(預期極少,因多為繁中,但可能混到「優化/返回/數據」等)。
- `npm run build` 不受影響(`docs/` 不進 build)。
