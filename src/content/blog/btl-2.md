## 領導方式模型
領導方式模型就是透過幾項指標來描述一個環境，MOI模型就是其中一種描述方式


### MOI
MOI 模型包含三個構面：Motivation（激勵）、Organization（組織）、Innovation（創新）。每個構面都代表領導者塑造環境的方式。
1. Motivation 激勵 - Motivation 指的是激勵行為，包含「獎勵」與「懲罰」。
常見形式包含：
- 清楚表揚與獎賞
- 給予成長機會
- 透明的後果、責任範圍
簡單說，就是讓人願意動起來、知道努力是有方向也有回報的。

2. Organization 組織 - Organization 指的是讓人能工作得有效率、有秩序。常見包含：
- 規則制定
- 流程設計
- 資源分配
- 角色定義
好的組織並不是增加限制，而是讓事情「可預期、有標準、每個人知道怎麼合作」。

3. Innovation 創新 - Innovation 指的是促進想像、鼓勵試驗、容許不同觀點的環境。
一個具創新力的團隊通常有以下特徵：
- 樂於討論
- 每個人都能提出想法
- 不追求聲音最大的人，而是追求最好的點子
- 敢於嘗試、容許失敗
創新不是「天才發光」而是「環境允許你說出你想到的事」。

## Tech Leader解決問題的方式
一名優秀的 Tech Leader 通常需要在三件核心任務之間保持平衡：
1. 理解問題（Problem Understanding）
2. 管理思維（Management Thinking）
3. 保證品質（Quality Assurance）

下面分別介紹領導者在這三方面常用的具體作法。
1. 理解問題 - 技術領導者首要任務不是寫程式，而是確保團隊真正理解問題是什麼。
    常見方法包括：
  - 細心閱讀規範：不假設、不想像，用文件與需求作為基礎。
  - 鼓勵成員閱讀規範：減少口耳相傳造成的誤差。
  - 有分歧時回到原始問題：避免爭論偏離核心。
  - 在進展後回頭審視需求：因為理解會加深，重新閱讀常能發現更多細節。
  - 反向驗證（逆向思考）：問自己「如果需求無法這樣達成，會是為什麼？」
  - 拆解問題：將模糊的需求拆成明確的子問題。
  理解問題不是一次完成，而是整個專案中的反覆動作。

2. 管理思維 - Tech Leader 不是 PM，但需要用管理的角度思考。
包括：
- 貢獻明智的idea
- 鼓勵借鑒有用的idea
- 完善團隊中其他人提出的idea
- 應該耐心聽取團隊成員解釋想法
- 批評idea時要明確，對事不對人
- 提供idea前，先自己嘗試
- 時間和人力不足時，先不用找尋新idea
- 設定優先順序：不是所有事都一樣重要
- 合理分配工作：把對的人放在對的位置
- 讓團隊保持資訊同步：減少誤會與重工
- 協助成員拆解任務並確定可行性
- 建立透明的決策紀錄（為什麼做這個決策、背景是什麼）
- 保護團隊免受外部干擾（明確溝通瓶頸、避免不必要插單）
- 管理思維的本質是「讓團隊能專注產出」

3. 保證品質 - Tech Leader 必須確保最後產出的品質達到團隊與產品所需的標準。
包含：
- 在專案進行中測量品質
- Survey階段時就必須考慮如何監測品質
- 衡量實施速度並保持隨時可切換方法
- 從專案外部來看，切換立基點更新看法
- 和客戶一同檢驗
- 如果專案做錯，要想辦法重振士氣
- 建立 code review 流程
- 制定 coding style、架構原則、API 規範
- 協助建立自動化測試與 CI/CD 流程
- 協助排查問題與追 root cause
- 在品質與開發速度之間做健康的取捨
品質不是最後才補救，而是從架構、流程、習慣開始預防。
